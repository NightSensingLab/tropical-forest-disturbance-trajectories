# Included And Additional Inputs

All paths are relative to the repository root. The primary frozen inputs in
the first table, selected annual EVI windows/weights and reference result
CSVs are included. `DATA_MANIFEST.csv` is the authoritative included-file
inventory. Large grid-level extraction panels and candidate feature parts
below are additional inputs and are not included in this upload.

Abbreviations:

- C: `runs/20260909-extended-sensitivities`
- E: `runs/20260904-expanded-control-pool`

## Primary Estimates, Classification And Fixed Cohorts

| Path | Purpose |
| --- | --- |
| `A/history_qualified_candidates.parquet` | First-event directory; 24,406 candidates |
| `A/matched_treatments.parquet` | 16,747 matched events, covariates and area |
| `A/fixed_matched_pairs.parquet` | 50,198 links, within-set weights and censoring |
| `A/common_support_weights.parquet` | 10,970 eligibility events and frozen standardization weights |
| `S08/matched_links.parquet` | Authoritative event censoring map read by primary and classification scripts |
| `S09/annual_matched_effects.parquet` | Primary annualized monthly effects and usable-month counts |
| `S09/monthly_matched_effects.parquet` | Month-threshold analysis input |
| `A/fixed_matched_event_window.parquet` | Included frozen window; also created by `recompute_current_standardized.py`; fixed cohort and composition input |

Key fields include `treatment_grid_id`, `event_year`, `event_type`,
`macroregion`, `relative_year`, `event_area_m2`, `treatment_lon`, `treatment_lat`,
`annual_matched_effect`, `usable_months`, `standardized_event_weight`,
`standardization_multiplier` and `censor_relative_year`. The censoring rule
retains years strictly before the censor year; a missing censor year indicates
no recorded subsequent censoring. Event-year keys must be unique at the
event level, and relative year must also be included for outcome rows.
The scripts enforce additional required fields and uniqueness contracts.

Fixed-cohort outputs are included and can be regenerated before the v32 A1 paired test:
`revision_v28_audit/fixed_cohort_sensitivity.csv`, `fixed_cohort_counts.csv`
and `fixed_cohort_manifest.json`. Year-specific bootstrap also needs
`revision_v28_audit/year_specific_event_table.parquet`, generated by
`run_v28_core.py`.

## Rebuilding Stage09 And Monthly Availability

`run_current_stage09.py` requires additional saved Stage08 inputs (only
`matched_links.parquet` is included):

- `S08/parts_monthly/event_year=YYYY/part.parquet`, YYYY=2004-2018.
- `S08/parts_16day/event_year=YYYY/part.parquet`, YYYY=2004-2018.
- `S08/matched_links.parquet`, `unit_event_catalog.parquet`,
  `collection_calendar.csv` and `subannual_manifest.json`.

Both monthly and 16-day parts are required by the existing Stage09 input gate.
The t0 availability decomposition reads monthly parts, links, common-support
weights and saved annual effects.

Stage08 assembly is the historical incremental procedure. It needs the
previous `01_data/upstream/TropicalRainforest_cloud_analysis/08_subannual_matched/`
catalog, calendar and 16-day parts, plus the current event-role catalog,
missing catalog, task manifest and exported CSVs. `build_current_sensitivity_inputs.py`
creates the current catalog using E's matching/history inputs and the frozen
Stage03 panel. The script does not recreate missing original annual exports.

## Separate Annual EVI Analysis And Figure 4

The annual construction under E uses a frozen annual EVI panel with an
observation threshold of 12. It differs from the primary monthly construction.
The sensitivity entry point reads E's matching/history files, configured
feature parts and Stage03 annual panel to build pre-event control risk sets.
Included frozen inputs/results relevant to this analysis are:

- `E/fixed_matched_event_window.parquet` (separate annual EVI outcome).
- `E/common_support_weights.parquet`.
- `E/pre_event_dynamic_control_pairs.parquet`,
  `pre_event_dynamic_control_window.parquet`.
- `E/ipcw_censoring_weights.parquet`, `ipcw_censoring_model.csv`.

The final Figure 4 generator reads these output tables:

- A and E: `standardized_event_type_bootstrap.csv`,
  `standardized_event_type_contrast.csv`.
- E: `pre_event_dynamic_standardized_bootstrap.csv`,
  `pre_event_dynamic_standardized_contrast.csv`,
  `ipcw_censoring_sensitivity.csv`.
- A: `audit/classification_current_summary.csv`.

## Historical Screening, Rematching And Distance Reconstruction

Rebuilding the matching cohort requires candidate-grid feature parts and
annual TMF/EVI inputs, rather than only selected controls. Paths are specified
in `E/config.json`, including:

- `02_analysis/integrated/TropicalRainforest_integrated_analysis/results/07_matched_control/work/features/obs12/yearYYYY/part_*.parquet`.
- `01_data/upstream/TropicalRainforest_cloud_analysis/03_combined_panel/parts/`.
- Historical screening and earlier control-history extraction records.
- E's `expanded_control_grid_universe.parquet`, history extraction parts,
  `history_qualified_annual.parquet` and `history_qualified_controls.parquet`.

Several historical builders also read earlier event catalogs, pairs and
windows listed as `legacy_*` or `restricted_run_root` in the configuration.
They remain external input requirements for the extraction/rematching workflows.

`run_matching_diagnostics.py` requires A's fixed pairs, matched treatments,
`history_qualified_controls.parquet` and all configured candidate feature
parts. It checks that reconstructed selections and distances agree with the
frozen 50,198 links; it is more expensive than a saved-result check.

`run_analysis_diagnostics.py` additionally reads A's
`spatial_block_distribution.csv`, `audit/matching_distance_event_summary.csv`
and `audit/extreme_match_sensitivity.csv`, all included. The latter is an archived comparison
table used only to report the difference from the previous diagnostic; its
old estimates are not the current scientific result. The event-distance table
can be generated by `run_matching_diagnostics.py`.
